# Jev 控制器的 vLLM 清单分类

这次审计覆盖本地 `Qwen3-0.6B_vLLM_parameter_checklist.html` 中的 **1,181 条记录**，来源快照标记为 vLLM `0.29.0+cu132`、审计日期 2026-09-30。[逐条 CSV](vllm_catalog_taxonomy.csv)保留每项原 ID、分组、接口路径、声明类型、默认值、声明范围、执行阶段、取值形态、控制类别和拟议的 Choice／步长规则。来源 HTML 本身说明这是一份测试计划；字段出现不等于运行时已验证，也不等于它的合法边界已完整核实。[分类脚本](../scripts/classify_vllm_checklist.py)可在清单变化后重新生成 CSV。

**1,181 条不等于 1,181 个能够中途调节的参数。**来源按接口统计了 1,051 条原生字段、65 条 Python 参数、5 个 CLI 开关、7 条测试步骤、1 条 Qwen 模板选项和 52 条排除的内部字段。同名参数可能在多个接口各出现一次。HTTP 请求字段不能直接塞进 Python `SamplingParams`；引擎启动和嵌套引擎配置也不能在当前已经加载的 `LLM` 对象的下一段中热修改。

分类先看**属于哪个接口、何时生效**，再看是数字、布尔、字符串、列表、对象还是联合类型。CSV 逐条区分 Python 采样、Python 调用入口与提示词构造、tokenize 接口、HTTP 请求、引擎启动与嵌套配置、嵌套请求结构、beam search、Qwen 模板、项目集成测试、测试步骤和内部排除项。脚本要求全部原 ID 唯一、全部记录都被分类；遇到未识别的接口会报错，不会悄悄套用通用步长。

每一行另有 `value_action_family` 与 `generic_step_eligibility`：前者只说明该**取值类型**可能怎样编辑，后者说明能否讨论数值步长，均不代表当前控制器可以调用它。按声明类型粗分：布尔 284、整数 222、浮点 60、字符串 150、列表等集合 77、映射 68、枚举 34、含集合的联合类型 22、其他联合／结构类型 28，以及仍需阅读具体结构或校验器的 236 项。复杂结构、可空值和嵌套数值不能仅凭字段名自动决定步长。

## 与当前 Python 调参最相关的 39 项

清单中 `Python / SamplingParams` 有 **39 条**。当前 `parameters.json` 改选的 20 项都能在其中找到；其余项也已列入 CSV，但“属于 SamplingParams”并不等于“适合按 Jev 分数动态调整”。CSV 的 `in_parameters_json` 列根据当前选择重新生成。

- **7 个一般数值调控项**：`temperature`、`top_p`、`top_k`、`repetition_penalty`、`min_p`、`presence_penalty`、`frequency_penalty`。
- **4 个结束条件项**：`stop`、`stop_token_ids`、`ignore_eos`、`min_tokens`。
- **3 个词表约束项**：`logit_bias`、`allowed_token_ids`、`bad_words`。
- **4 个观测项**：`logprobs`、`prompt_logprobs`、`logprob_token_ids`、`flat_logprobs`。
- **6 个输出或流式呈现项**：`detokenize`、`skip_special_tokens`、`spaces_between_special_tokens`、`include_stop_str_in_output`、`output_kind`、`stream_interval`。
- **3 个实验程序自己控制的值**：`n`、`seed`、`max_tokens`。
- **7 个需要单独核对前置条件的功能项**，以及 **5 个内部或派生字段**。

以上共 39 项。只有第一组适合统一讨论“升／降和步长”；`min_tokens` 是受下一次生成长度约束的条件性例外。观测和显示项会列给审计者看，但不能因为正确性低就把它们当作纠错按钮。`max_tokens`、`seed`、`n` 由实验程序控制；不会把剩余 token 预算交给 Jev 调节。

## 数值型参数的首版候选规则

Jev 先为每项选择 `keep`、`increase` 或 `decrease`。选定方向后，程序按**调控范围跨度 ÷ 分母**生成 1、2、3 倍步长的具体候选，再让 Jev 选择。调控范围不同于参数合法上限。整数候选先转成整数、去重；越界或重复的候选直接删除，靠近边界时不强求一定有三个。这些分母是**待实验验证的起点**，不是 vLLM 官方推荐值。

- `temperature`：调控范围 0～2，分母 **20**，步长 0.1。
- `top_p`：0.01～1，分母 **100**，步长 0.0099；当前值 0.95 已接近上限。
- `min_p`：0～1，分母 **100**，步长 0.01。
- `repetition_penalty`：按当前项目边界 1～1.5，分母 **20**，步长 0.025。
- `presence_penalty`、`frequency_penalty`：各为 −2～2，分母 **100**，步长 0.04。
- `top_k`：建议单独采用实用调控范围 1～101，分母 **20**，整数步长 5。现有上限 1,000,000 只用于校验，不能拿来算步长；0／−1 是独立的关闭状态。
- `min_tokens`：有条件采用调控范围 0～128、分母 **20**，整数步长约 6；程序还必须检查它不超过下一段实际的 `max_tokens`。

布尔值只有保持、打开、关闭，没有幅度。可空数值先从核实过的候选中选择启用起点；已有数值后，当前控制器提供受边界约束的 1、2、3 步增减，也可关闭回到 `null`。`logprobs`、`prompt_logprobs` 属于观测设置，不是答案质量控制。字符串、列表和对象必须有经过核实的具体字符串、词、token ID 或对象条目，才能提出设置、添加、移除、清空等动作；单靠类型定义无法生成安全内容。`logit_bias` 更要先确定 token ID，再单独控制偏置数值。结构化输出、推测解码等条件性功能也不能继承普通数字的通用步长。

对其余接口，即使声明为整数或浮点，也只标为“有条件讨论方向”：必须先确认所属接口确实会被当前程序调用、字段的完整合法边界、可用的实用调控窗口及改变后何时生效。启动参数通常需要重建引擎；HTTP 和其他 Python 入口属于不同实验路径。没有这些证据就不为它们指定 1/20 或 1/100，更不把它们放进当前逐段 Choice。

**当前代码已为代表子集实现 Score、方向 Choice、具体值 Choice 的类型化请求。**这份分类仍覆盖更广的清单，并不意味着 1,181 条接口都已实现或实测。其他字段仍需针对接口、边界和运行效果单独验证。
